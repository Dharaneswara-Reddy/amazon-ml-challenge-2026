# Plan v3 — from 0.961 public toward the top 100 (≥ 0.982)

Status: PROPOSED, awaiting approval. Evidence: `research_notes/v3/A_error_analysis.md` (loss decomposition, reproduces
holdout 0.9715 exactly), `B_blocking_recall.md` (measured new blocking passes), `C_speed.md` (measured LightGBM and
blocking benchmarks), `D_methods_france.md` (methods, France, test-time adaptation).

## 1. Diagnosis — why we are at 0.961 while the top 100 are at ≥ 0.982

Holdout loss is 2.85 points (1 − 0.9715). Oracle gain from fixing each category alone:

| Category | Pairs | Oracle gain (points) |
|---|---|---|
| True pairs never generated by blocking (5.5% of true pairs) | 20,863 | **+2.05** |
| Decision false negatives (mean p 0.43) | 4,952 | +0.45 |
| False positives on entities that have matches | 993 | +0.21 |
| Right record lost at one-to-one to a rival | 1,380 | +0.14 |
| False positives on singletons (81 entities zeroed) | 97 | +0.07 |

- **The ceiling on today's candidates is 0.980** even with perfect decisions. That is below the top-100 bar, so no amount
  of classifier or decision work can get us there. Blocking recall is the bottleneck.
- The decision layer is already near-optimal: calibration on holdout is almost perfect and k* is only slightly
  conservative.
- Local → public gap is 0.010 (0.9715 → 0.961); for the baseline it was 0.06. The prior-shift correction worked; the
  remainder is not attributable further without test labels. By a model-expectation proxy France looks no worse than
  the US or India.
- **Why blocking misses:** 96% of misses are never generated by any pass. 74% share no token rare enough for our
  token pass (df cap 100), though *combinations* of common tokens are rare, e.g. "1940 + fisher" has df 6 where every
  single token of "Liberty Trust, 1940 Fisher Rd" is common. Miss types:

  | Type | Share of misses |
  |---|---|
  | Right address empty or short | 25% |
  | Typo'd or extra-word name | 23% |
  | Web-domain or concatenated name | 15% |
  | Non-Latin script | 13% |
  | Same name, other address | 12% |
  | Name differs, address agrees | 12% |
- **A usable "generator signature":** distractors move the house number UP by specific offsets (+1..+5, +7, +9, +11,
  +13; e.g. +13 occurs 5,125× on non-matches vs 98× on matches) while true copies drop or truncate digits or change by
  ±1/±2. Our number features ignore the sign. A quick post-hoc test gained +0.056 on holdout.

## 2. Changes, ranked by expected gain

### P1. Blocking v3: compound-key passes + learned cut — expected **+1.0 to +1.3 points** (main lever)
Measured on a 5% sample of right records against all train S1 (B §Q3). Greedy forward selection of new passes,
each added on top of the previous:

| Step | Recall | Candidates per right record |
|---|---|---|
| v2 (today) | 94.50% | 3.0 |
| + `px`: 6-char prefix of space-stripped name × (address number or address word) | 96.87% | 5.2 |
| + `hs`: address number × address word | 97.65% | 8.1 |
| + `n2`: unordered pair of name words | 97.99% | 9.5 |
| + `na`: name word × address word | 98.17% | 12.1 |
| + `phx`: whole phonetic-skeleton name | 98.28% | 12.9 |

- Each pass: keys hashed to UBIGINT and scoped by country, left document-frequency cap 30–50, IDF-summed score, top-5
  per right, 8 right-hash buckets. Estimated 10–15 min per split for the passes.
- **The cut:** replace "top-3 per right by linear score" with **linear top-1 OR small-GBDT p ≥ 1e-3**. The GBDT has
  about 17 cheap features (JW of phonetic and space-stripped names, address Jaccard, pass scores, address length...)
  and is trained on fit-group rights. Measured: **98.2% recall at 1.64 pairs per right**, against 94.5% at 3.0 today.
  - About 7.7 candidates per S1 in train and about 9 in test, against 14 and 17 today, so everything downstream gets
    faster.
  - Fallback: top-2 OR p ≥ 1e-3 gives 98.27% at 2.4 pairs per right.
- New normalized columns: `name_strip` (spaces removed) and `name_phn` (phonetic skeleton, B §implementation), built
  in Python in normalize with a per-word cache.
- **Why the range:** the recovered pairs are harder than average, so the model will not win every one. Recall-limited
  oracle headroom rises by about 1.4 points; we expect 70–90% of it.
- **France:** 83–86% of French test records have a rare-enough compound key, the same as US and India, so the passes
  work without French training data.

### P2. Features v3 — expected **+0.15 to +0.3**
1. **Signed house-number features:** signed difference of the first/max number, a flag for whether the offset is in
   the distractor set (learned from train counts, not hard-coded), digit-drop/truncation flags, and unit-letter/"bis"
   suffix handling. Measured +0.056 as a post-hoc add-on; inside the model it should be more.
2. **New-pass evidence:** in_px/in_hs/in_n2/in_na/in_phx flags and scores, JW(name_phn), JW(name_strip), and the
   blocking GBDT's p as a feature.
3. **Crowded names / empty address:** number of S1 in the country with the same `name_core`, number of the right's
   candidates sharing its name, right address empty × name frequency. These target the 7.3% miss / FP pattern.
4. **France-safe normalization:**
   - elision (l'/d'/qu')
   - French legal forms: SARL/SAS/SASU/EURL/SA/SNC/SCI/EI/Sté/Ets/Cie, with any gaps checked
   - "bis/ter" as number suffixes
   - accents folded consistently
   All hand-written rules; no external data.

### P3. Decision and test adaptation — expected **+0.05 to +0.2 on public** (not measurable locally)
1. **Per-country EM prior shift:** the shift is currently global, pooled across countries. France has no training
   prior, so a separate shift lets its match rate adapt.
2. **Second-choice reassignment at one-to-one:** when a right's best S1 doesn't select it, fall back to its second
   choice if that clears the rule. +0.02 to +0.05.
3. Keep the tune-only rule choice (expected-F vs threshold).

### P4. Model settings — accuracy-neutral or better, and faster
- `learning_rate` 0.1 → **0.2**: measured 27% faster *and* lower logloss at sample scale (C §2).
- `num_leaves` 127: lower logloss (0.01563 vs 0.01610) but about 1.5× slower per tree. Decide by one full-scale
  comparison on the new features, time permitting.

### Deliberately not doing now (tried or judged low value)
- **S2↔S3 clustering / transitivity.** +0.09 pp recall only; copies are less alike to each other than each is to S1.
- **Char 4-gram pass.** Ran out of memory; `px` covers the same cases cheaply.
- **Multilingual embedding model** (e5-small, MIT) **+ faiss.** 1–1.5 days on CPU for 30M pairs; the compound keys
  already reach the ~98.5% practical ceiling. Revisit only if time remains.
- **France pseudo-labeling / self-training.** Error compounding is costly under F0.5; optional only after P1–P3 are in.

## 5. Expected outcome (honest)

- **Local holdout:** 0.9715 → about **0.983–0.987**. Mostly from recall; the new ceiling is about 0.992 instead of
  0.980.
- **Public:** about **0.973–0.978** if the 0.010 local→public gap persists. Per-country prior shift and France
  normalization aim to shrink that gap.
- **0.99** would be above the current leaders (about 0.988). It would need both the full recall gain and a closed
  local→public gap. That is a stretch goal, not a forecast.

## 6. Risks and guards
- **Pair explosion on common key combinations.** Guard with the left df caps (30–50) plus top-5 per right; the
  sampled runtimes were 3–29 s per pass on 5% of rights. Spill goes to disk (artifacts/tmp), not /tmp (RAM-backed).
- **Memory, 15 GB with swap already full.** Keep DuckDB 5 GB and 6 workers. Concurrency only with split budgets.
  The resume options are already in place.
- **Leakage.** The blocking-cut GBDT and every learned table are fitted on the fit group only. Holdout is scored once.
- **Competition rules.** No external data: the phonetic rules and French rules are hand-written, and the distractor
  offsets are learned from train. Models remain LightGBM (MIT).
