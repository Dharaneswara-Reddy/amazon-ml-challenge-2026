## 2. Blocking misses (the 2-pt problem) - what they are
(a03_blockmiss.py, a04_miss_patterns.py; learned/ranker.json)
- Every missed right record already has its full K=3 candidates. On the ranker's union sample, recall is
  0.9425@1, 0.9500@3, **0.9519 plateau at K=15** -> the top-K cut costs only ~0.2 pts of recall; **~4.8% of true
  pairs are never generated by any pass**. More K will not fix it; new generation keys are needed.
- Misses are split evenly S2/S3 (5.45% vs 5.47% miss rate) and US/India (10,775 / 10,088).
- Many misses look *easy* to a human: "Big Business Private Limited" vs "Big-Business Private Ltd" (R address empty),
  "Owen's Supreme Grill" vs "Owenssupremegrill.Com" (same house number/street), Devanagari/Gujarati/Bengali names with
  identical addresses.

Pattern categories over ALL 382,075 holdout true pairs (mutually exclusive, first rule wins):

| category | true pairs | blocking misses | miss rate | decision FN | o2o FN |
|---|---|---|---|---|---|
| name noisy, R address present | 94,330 | **6,708** | 7.1% | 898 | 8 |
| R name concatenated / domain-style (`owenssupremegrill`) | 21,434 | **2,884** | 13.5% | 18 | 4 |
| R name non-Latin script (transliteration) | 27,609 | **2,766** | 10.0% | 233 | 2 |
| R address empty, name noisy | 5,362 | **2,703** | **50.4%** | 451 | 326 |
| R address empty, name_core equal | 11,403 | 2,286 | 20.1% | 1,405 | 905 |
| name replaced (JW core < 0.6), address only | 8,415 | 1,800 | 21.4% | 435 | 132 |
| name_core equal, address present | 213,522 | 1,716 | 0.8% | 1,512 | 3 |

Crowding: for true pairs with equal name_core, miss rate is 0.02% when the R name_core is unique in S1, 0.09% for
2-3 S1 sharing it, 2.6% for 4-10, **7.3% for >10** (4,677 misses). The generator reuses name vocabularies heavily
(e.g. "classic education", "big business pvt ltd"), and window-3 sorted neighbourhood + df-capped token passes
cannot enumerate a crowded name block; the address must break the tie inside the name block.
Among misses: 60% share at least one address number with the true S1; postal is never available.

### 2b. Which new blocking keys would recover the misses (a05_keys.py, full train volume)
Exact-equality keys, blocks capped at <= cap S1 records per key value; pairs/R = generated pairs per right record
on full train (10.3M right records); "covers misses" = share of the 20,863 holdout blocking misses whose key is equal.

| key | cap | pairs/R | covers all true pairs | covers misses |
|---|---|---|---|---|
| name_core without spaces (`owenssupremegrill`) | 20 | 1.02 | 0.513 | 0.112 |
| name_core without spaces | 100 | 7.84 | 0.648 | 0.313 |
| name_core without spaces + state/admin | 20 | 1.26 | 0.623 | **0.220** |
| house number + street name | 20 | 0.66 | 0.479 | 0.181 |
| house number + city + admin | 20 | 0.81 | 0.418 | 0.115 |
| street name + admin | 20 | 2.03 | 0.505 | 0.203 |
| street name + admin | 100 | 5.17 | 0.573 | 0.252 |
| name skeleton + admin | 20 | 1.36 | 0.608 | 0.146 |
| first two name tokens + admin | 20 | 1.57 | 0.639 | 0.161 |
| sorted address numbers + admin | 20 | 2.34 | 0.423 | 0.074 |

- **Union of all 8 keys at cap 20 covers 11,600 / 20,863 = 55.6% of misses** for roughly +11 pairs/R before dedup
  (current union is ~8 pairs/R; the top-3 cut afterwards keeps the output size unchanged).
- The current linear ranker would score **72% of missed true pairs above the right record's current 3rd candidate
  (68% above its current best candidate)**: these are generation failures, not ranking failures.
- 10,200 misses (49%) are both covered by the new keys and would survive the top-3 cut.
  => oracle upper bound for this fix ~0.49 x 2.05 = **~1.0 pt**; with the classifier catching ~85% of them,
  **~+0.8 pt** expected. Remaining misses are mostly R-address-empty + crowded name (inherently ambiguous) and
  transliterated names.

## 4. Generator signatures (a07_signature.py, log out/a07.log)
### 4a. House-number edit type separates true copies from distractors
Holdout candidate pairs with name JW(core) >= 0.9, relation of the first address number (R vs L):

| relation | true | non-match | true rate | FP (sel) | dec FN |
|---|---|---|---|---|---|
| equal | 243,435 | 74,664 | 0.765 | 296 | 784 |
| a number missing on one side | 38,733 | 68,119 | 0.363 | 196 | 1,903 |
| R = L minus last digit (truncation) | 4,294 | 3,828 | 0.529 | 34 | 126 |
| R = L minus an inner digit | 3,216 | 2,012 | **0.615** | 3 | 24 |
| R = L plus extra digits | 2,069 | 15,357 | 0.119 | 15 | 31 |
| +-1 | 1,919 | 16,219 | 0.106 | 24 | 184 |
| +-2..20 | 5,576 | 79,051 | 0.066 | 157 | 422 |
| +-21..200 | 7,334 | 78,653 | 0.085 | 48 | 224 |
| other | 17,361 | 227,768 | 0.071 | 66 | 319 |

**Signed difference (R - L) is a strong distractor signature.** Non-matches are skewed positive and odd:
+1: 11,126, +2: 8,504, +3: 7,503, +4: 6,802, +5: 6,740, **+6: 1,969**, +7: 6,171, **+8: 1,588**, +9: 5,188,
**+10: 912**, +11: 5,093, **+12: 842**, +13: 5,125, then +15: 742 (flat ~500-750 beyond). Negative diffs are much
rarer (-1: 5,093, -2: 3,062, -5: 1,446). True matches are symmetric and concentrated at +-1/+-2 (-2: 830, -1: 981,
+1: 938, +2: 760, +13: 98). So the distractor generator adds roughly {+1..+5, +7, +9, +11, +13} to the house
number; true noise deletes/truncates digits or makes +-1/+-2 typos. The v2 number features (nr_min_rel_diff,
nr_class, nums_conflict) are unsigned / relative: **add signed diff, diff parity, "diff in {1,2,3,4,5,7,9,11,13}",
and digit-deletion/truncation flags** (per first number and per any number pair). Target: 157+24+48 = ~230 FPs and
~800 dec FNs in the numeric-nudge rows.

### 4b. GT structure and S2/S3 siblings
- Matches per S1 by source: (S2,S3) = (1,1) 270k, (1,2) 251k, (2,1) 223k, (2,2) 208k, (1,3) 140k, ... (0,k) and (k,0)
  common -> no usable per-source cardinality constraint.
- Siblings (two true copies of the same S1, 112k pairs): name JW R-R 0.926 vs L-R 0.960; name_core exact R-R 44%
  vs L-R 64%; address JW R-R 0.791 vs L-R 0.843. **Copies are generated independently from S1**; S2+S3 clustering
  before matching would be *weaker* evidence than direct S1 matching. Not worth building.
- Pseudo-brand single-token names (not in S1 vocab, JW<0.75): 41k holdout candidate pairs, true rate 0.154 vs 0.234
  overall -> no clean signature; these are genuine "name replaced, address kept" copies (8.4k true pairs) that need
  an address-only path (strong address match + number relation), 1,800 of them are blocking misses.

### 4c. Quick experiment: number-signature correction on top of stage-2 p (a08_numfeat_exp.py)
Post-hoc LightGBM on [logit p2, signed first-number diff d1, missing code, truncation, inner-digit deletion,
plus-digits, #numbers each side, #unshared numbers each side], cross-fitted on tune (2 folds), decision params refit
on tune exactly like the pipeline, scored on holdout:
- baseline (same procedure, p2 only): **0.971512**, FP 1,090, TP 354,880
- + number signature: **0.972076 (+0.056 pts)**, FP 955 (-135), TP 354,830 (-50)
- signed diff d1 has by far the largest gain of the new features. Built into the stage-1/2 feature set (where it
  can interact with name-noise features and be applied per number, not only the first), expect +0.05 to +0.10 pts.

## 6. Ranked fixes (estimated holdout macro-F0.5 gain)
1. **New blocking keys in the union before the ranker** (section 2b): exact-equality passes on
   `nospace(name_core)+admin`, `house#+street`, `street+admin` (cap 20-100), `name_skel+admin`,
   `first-2-name-tokens+admin`, `house#+city+admin`, `nospace(name_core)` (cap 100), `sorted nums+admin`, each with
   a block-size cap. They cover 55.6% of current misses, 49% would survive the existing top-3 ranker. Retrain the
   ranker on the new union; keep K=3. **Estimated +0.8 to +1.2 pts** (oracle +1.3). This is the only fix that can
   get past 0.980.
2. **Address-only generation path for right records whose name is unusable** (non-Latin script: 2,766 misses at 10%
   miss rate; pseudo-brand replaced names such as "Xylocira", "Ectocira", "Nylasoliri": 1,800 misses at 21%;
   domain-style concatenations: 2,884 at 13.5%): candidates from address words + house number, ranked by
   address similarity only. Partly overlaps fix 1. **+0.2 to +0.4 pts.** For France, keep the keys
   script- and country-agnostic (no US/India-specific tokens).
3. **Signed house-number features** (section 4): signed R-L diff, whether the diff is in the distractor set
   {+1..+5,+7,+9,+11,+13}, parity, digit-truncation / inner-deletion flags, computed for the first number AND
   for the best-aligned number, plus counts of unshared numbers each side. Measured post-hoc **+0.056 pts
   (FP 1,090 -> 955)**; **+0.05 to +0.10 in-model**. Cheap: features.py/textdiff.py only.
4. **Crowded-name / R-address-empty handling** (1,864 dec FNs + 170 FPs + 4,989 blocking misses): let the name-only
   pass enumerate *all* S1s sharing the exact name_core in the same country (cap ~20) rather than a window of 10, and
   add stage-2 features "number of S1 candidates with identical name_core for this R" and "rank of this L among
   them". Most of these are inherently ambiguous (F0.5 prefers abstaining), so the gain is limited:
   **+0.05 to +0.15 pts**, mainly from n=1/n=2 entities where the one copy has no address.
5. **One-to-one losses** (1,380 FN, oracle +0.135): 94% are right records whose best lid is a rival. Mostly the same
   empty-address ambiguity; a second-choice pass that gives an entity its R record when the rival entity already has
   k* picks and the R record's score gap is small. **+0.02 to +0.05 pts**.

Not worth time: the decision rule and calibration (calibration already within ~1-2 pts per decile, tune grid flat to
0.0015, perfect decisions on current candidates cap at 0.980); S2+S3 clustering before matching (siblings are less
similar to each other than to S1); per-source cardinality constraints (none in the GT).
